Entrega 5: cruzar tablas

0 de 6 resueltos

Casi nunca tienes los datos en una sola tabla: los pedidos guardan el id del cliente y el nombre vive en otra parte, así que hay que cruzarlas por esa columna común. En Python, la forma rápida es construir primero un diccionario que vaya del id al registro y consultarlo en cada vuelta; en SQL lo hace JOIN. La pregunta clave siempre es qué hacer con las filas que no encuentran pareja: INNER JOIN las descarta y LEFT JOIN las conserva con NULL.

Cómo practicar

  1. Descarga el archivo y ábrelo en tu editor.
  2. Completa las funciones y las consultas.
  3. Ejecuta python entrega_05.py para ver qué casos pasan. Solo necesitas Python: SQLite viene incluido.
  4. Si te atascas, pide una pista. Al terminar, compara con la solución.

Python

1. ¿De quién es el pedido?

Escribe nombres_de_pedidos para que devuelva, en el orden de pedidos, el nombre del cliente de cada pedido. Cada pedido es un diccionario con id y cliente_id, y cada cliente uno con id y nombre. Si el cliente no existe, pon "Desconocido".

  • nombres_de_pedidos([{"id": 10, "cliente_id": 2}, {"id": 11, "cliente_id": 1}, {"id": 12, "cliente_id": 2}], [{"id": 1, "nombre": "Ana"}, {"id": 2, "nombre": "Luis"}, {"id": 3, "nombre": "Sol"}]) devuelve ["Luis", "Ana", "Luis"]
  • nombres_de_pedidos([{"id": 20, "cliente_id": 3}, {"id": 21, "cliente_id": 9}], [{"id": 3, "nombre": "Sol"}]) devuelve ["Sol", "Desconocido"]
  1. Buscar el cliente recorriendo toda la lista en cada pedido funciona, pero repite el mismo trabajo una y otra vez.
  2. Prepara antes del bucle un diccionario cuya clave sea el id del cliente.
  3. Al consultar un diccionario puedes indicar un valor por defecto para cuando la clave no está; así no se cae ni se pierde el pedido.
Ver solución 
def nombres_de_pedidos(pedidos, clientes):
    nombre_por_id = {c['id']: c['nombre'] for c in clientes}
    return [nombre_por_id.get(p['cliente_id'], 'Desconocido') for p in pedidos]

El diccionario se construye una vez y cada búsqueda es inmediata, en lugar de recorrer la lista de clientes por cada pedido. Filtrar los pedidos sin cliente parece limpio, pero cambia la longitud del resultado y ya no se sabe qué nombre corresponde a qué pedido; get con un valor por defecto conserva uno por pedido.

2. Ventas con precio

Para cada venta cuyo producto existe en el catálogo, muestra el id de la venta, el nombre del producto y el importe (cantidad por precio). Las ventas de productos que no están en el catálogo no salen. Ordena por id de venta.

  1. Las dos tablas tienen una columna id, pero no significan lo mismo: ¿qué columna de ventas apunta a un producto?
  2. Como las ventas sin producto no deben salir, te sirve el cruce que solo conserva las filas con pareja en ambos lados.
  3. Pon un alias corto a cada tabla para dejar claro de cuál sale cada columna, en especial en el ON y en el ORDER BY.
Ver solución 
SELECT v.id AS venta, p.nombre AS producto, v.cantidad * p.precio AS importe
FROM ventas AS v
JOIN productos AS p ON p.id = v.producto_id
ORDER BY v.id;

JOIN a secas es un INNER JOIN: la venta 3 apunta al producto 9, que no existe, y desaparece sola. La trampa es unir por id con id: la consulta no da error y devuelve filas con buena pinta, pero empareja cada venta con el producto que tiene su mismo número, no con el que vendió.

Python

3. Clientes sin pedidos

Escribe sin_pedidos para que devuelva los nombres de los clientes que no tienen ningún pedido, en el orden de clientes. Cada cliente tiene id y nombre, y cada pedido tiene id y cliente_id.

  • sin_pedidos([{"id": 1, "nombre": "Ana"}, {"id": 2, "nombre": "Luis"}, {"id": 3, "nombre": "Sol"}], [{"id": 1, "cliente_id": 2}, {"id": 2, "cliente_id": 2}]) devuelve ["Ana", "Sol"]
  • sin_pedidos([{"id": 5, "nombre": "Rita"}, {"id": 6, "nombre": "Tito"}], [{"id": 6, "cliente_id": 5}]) devuelve ["Tito"]
  1. Primero reúne los ids de los clientes que sí compraron; no te importa cuántas veces compró cada uno.
  2. Fíjate bien en qué campo del pedido identifica al cliente: el pedido también tiene su propio id.
  3. Después recorre los clientes en orden y quédate con los que no están en ese conjunto.
Ver solución 
def sin_pedidos(clientes, pedidos):
    con_pedido = {p['cliente_id'] for p in pedidos}
    return [c['nombre'] for c in clientes if c['id'] not in con_pedido]

Un conjunto responde al instante si un id ya apareció, así que basta con dos pasadas. Es el equivalente en Python a buscar filas sin pareja. Confundir id con cliente_id es el error más común al cruzar datos, y suele pasar desapercibido cuando los números se parecen.

4. Productos que nadie compró

Muestra el nombre de los productos que no aparecen en ninguna venta, ordenados alfabéticamente. Ojo: alguna venta puede tener el producto_id vacío (NULL) por un error de carga.

  1. Necesitas un cruce que conserve todos los productos, aunque no tengan ninguna venta.
  2. Cuando un producto no encuentra pareja, las columnas de ventas llegan vacías en su fila.
  3. Nada es igual a NULL, ni siquiera otro NULL: para preguntar si un valor falta hay un operador propio.
Ver solución 
SELECT p.nombre
FROM productos AS p
LEFT JOIN ventas AS v ON v.producto_id = p.id
WHERE v.id IS NULL
ORDER BY p.nombre;

LEFT JOIN deja todos los productos y rellena con NULL las columnas de ventas cuando no hay pareja; el WHERE se queda justo con esas filas. v.id = NULL nunca es verdadero y devuelve una tabla vacía sin dar error. Otra trampa: WHERE id NOT IN (SELECT producto_id FROM ventas) tampoco devuelve nada en cuanto hay un producto_id NULL, y esto pasa en cualquier motor, no solo en SQLite.

Python

5. Total por cliente

Escribe total_por_cliente para que devuelva un diccionario que vaya del nombre de cada cliente a la suma de los importes de sus pedidos. Los clientes sin pedidos aparecen con 0, y los pedidos de clientes que no existen se ignoran. Cada cliente tiene id y nombre, y cada pedido cliente_id e importe. No hay dos clientes con el mismo nombre.

  • total_por_cliente([{"id": 1, "nombre": "Ana"}, {"id": 2, "nombre": "Luis"}, {"id": 3, "nombre": "Sol"}], [{"cliente_id": 1, "importe": 10}, {"cliente_id": 3, "importe": 5}, {"cliente_id": 1, "importe": 7}]) devuelve {"Ana": 17, "Luis": 0, "Sol": 5}
  • total_por_cliente([{"id": 4, "nombre": "Rita"}], [{"cliente_id": 4, "importe": 3}, {"cliente_id": 8, "importe": 50}]) devuelve {"Rita": 3}
  1. Si solo recorres los pedidos, los clientes que no compraron nunca llegan a aparecer en el resultado.
  2. Empieza con un acumulador que ya tenga a todos los clientes con total 0, usando su id como clave.
  3. Al sumar, comprueba que el cliente del pedido esté en el acumulador; al final, traduce cada id a su nombre.
Ver solución 
def total_por_cliente(clientes, pedidos):
    totales = {c['id']: 0 for c in clientes}
    for p in pedidos:
        if p['cliente_id'] in totales:
            totales[p['cliente_id']] += p['importe']
    return {c['nombre']: totales[c['id']] for c in clientes}

Es un LEFT JOIN con suma hecho a mano: el lado que no se puede perder son los clientes, así que el acumulador parte de ellos. Construir el resultado solo desde los pedidos funciona hasta que aparece un cliente sin compras y desaparece del informe. Acumular por id y no por nombre evita mezclar datos si algún día dos clientes se llaman igual.

6. Resumen de todos los clientes

Para cada cliente, incluidos los que no han hecho pedidos, muestra su nombre, cuántos pedidos tiene y la suma de sus importes (0 si no tiene). Los pedidos de clientes que no existen no cuentan. Ordena por nombre.

  1. Parte de clientes y cruza con pedidos de forma que ningún cliente se quede fuera.
  2. Un cliente sin pedidos sigue ocupando una fila tras el cruce, con las columnas de pedidos en NULL. Piensa qué cuenta cada forma de COUNT en esa fila.
  3. La suma de un grupo sin valores no es 0 sino NULL: hay una función que cambia un NULL por el valor que le digas.
Ver solución 
SELECT c.nombre, COUNT(p.id) AS pedidos, COALESCE(SUM(p.importe), 0) AS total
FROM clientes AS c
LEFT JOIN pedidos AS p ON p.cliente_id = c.id
GROUP BY c.id, c.nombre
ORDER BY c.nombre;

Tras el LEFT JOIN, Luis tiene una fila con p.id en NULL: COUNT(*) la cuenta como un pedido y COUNT(p.id) no. Agrupar por c.id además del nombre evita juntar a dos clientes que se llamen igual. COALESCE hace falta porque SUM de un grupo sin valores devuelve NULL, y eso pasa igual en todos los motores.
