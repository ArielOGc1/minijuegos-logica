Entrega 6: dos punteros y orden

0 de 6 resueltos

Con dos punteros recorres una secuencia desde dos sitios a la vez, por ejemplo uno desde cada extremo o uno en cada lista, y en cada paso avanzas el que toca según lo que ves. Funciona especialmente bien cuando los datos están ordenados, porque el orden te dice qué puntero mover sin tener que volver atrás. En SQL el orden lo pones tú con ORDER BY, y LIMIT con OFFSET te dejan quedarte con una porción concreta: los primeros, la segunda página o el segundo más alto.

Cómo practicar

  4. Si te atascas, pide una pista. Al terminar, compara con la solución.

Python

1. Se lee igual al revés

Escribe es_palindromo para que devuelva True si texto se lee igual de izquierda a derecha que de derecha a izquierda, teniendo en cuenta solo letras y dígitos y sin distinguir mayúsculas de minúsculas. Espacios, comas, signos de exclamación y demás se ignoran. Los textos de prueba no llevan tildes.

  • es_palindromo("Anita lava la tina") devuelve True
  • es_palindromo("Hola") devuelve False
  • es_palindromo("Sal, sol") devuelve False
  1. Pon un índice al principio y otro al final del texto, y acércalos hacia el centro.
  2. Si el carácter de un lado no es letra ni dígito, avanza solo ese índice y vuelve a mirar. Los textos traen una forma directa de hacer justo esa pregunta.
  3. Compara los dos caracteres ya pasados a minúscula: a la primera diferencia ya sabes la respuesta, y si los índices se cruzan sin encontrar ninguna, es palíndromo.
Ver solución 
def es_palindromo(texto):
    i, j = 0, len(texto) - 1
    while i < j:
        if not texto[i].isalnum():
            i += 1
        elif not texto[j].isalnum():
            j -= 1
        elif texto[i].lower() != texto[j].lower():
            return False
        else:
            i += 1
            j -= 1
    return True

Los dos índices avanzan hacia el centro y cada carácter se mira una sola vez, sin crear copias del texto. Quitar a mano espacios y comas parece suficiente con los ejemplos, pero en cuanto aparece un signo que no tenías previsto, como ¡ o !, el texto ya no es simétrico; isalnum decide carácter por carácter sin tener que listar todos los signos. También vale limpiar primero y comparar con [::-1], siempre que filtres con isalnum.

2. El podio de ventas

Muestra el nombre y las unidades de los 3 productos más vendidos, de más a menos unidades. Si dos productos empatan en unidades, va primero el de nombre alfabéticamente menor.

  1. Primero ordena toda la tabla y después quédate con las primeras filas: en SQL esas dos cosas van en cláusulas distintas.
  2. Por defecto el orden es de menor a mayor; para los más vendidos necesitas el contrario.
  3. ORDER BY admite varias columnas separadas por comas, y la primera manda: la segunda solo decide entre filas empatadas en la primera.
Ver solución 
SELECT nombre, unidades
FROM productos
ORDER BY unidades DESC, nombre
LIMIT 3;

El LIMIT se aplica después de ordenar, así que primero se decide el orden completo y luego se cortan 3 filas. El orden de las columnas en ORDER BY importa: poner nombre delante ordena alfabéticamente y las unidades ya casi no cuentan. Sin el desempate por nombre, qué producto entra en un empate dependería del motor. LIMIT vale en SQLite, PostgreSQL y MySQL; SQL Server usa TOP u OFFSET ... FETCH.

3. Registros sin repetir

Un sistema guarda los ids de los registros procesados en una lista ordenada de menor a mayor, pero algunos se procesaron varias veces. Escribe ids_unicos para que devuelva una lista nueva con cada id una sola vez, en el mismo orden.

  • ids_unicos([101, 101, 102, 105, 105, 105]) devuelve [101, 102, 105]
  • ids_unicos([3, 4, 5]) devuelve [3, 4, 5]
  1. Como la lista está ordenada, los repetidos siempre quedan juntos, uno detrás de otro.
  2. Basta con comparar cada id con el último que ya guardaste en el resultado, no con todos.
  3. Ojo con el primer id (aún no hay ningún “último guardado”) y con el último de la lista: los dos tienen que entrar.
Ver solución 
def ids_unicos(ids):
    unicos = []
    for x in ids:
        if not unicos or unicos[-1] != x:
            unicos.append(x)
    return unicos

Un puntero recorre la lista y el otro es el final del resultado: como lo repetido está junto, basta comparar con lo último guardado. Comparar cada elemento con el siguiente también es una idea correcta, pero el bucle hasta len(ids) - 1 se olvida del último id y falla con listas de un solo elemento. sorted(set(ids)) daría lo mismo aquí, pero solo porque la lista ya venía ordenada.

4. La segunda página

La app muestra los usuarios del registro más reciente al más antiguo, 3 por página. Si dos usuarios se registraron el mismo día, va primero el de id menor. Muestra el id y el nombre de los usuarios de la página 2.

  1. Las fechas están guardadas como texto con el formato año-mes-día, así que ordenarlas como texto las deja en orden cronológico.
  2. Necesitas dos criterios de orden: la fecha, de la más nueva a la más vieja, y el id para los empates.
  3. Para llegar a la página 2 tienes que saltarte la página 1 entera. ¿Cuántas filas son? Generalizando, la página n se salta (n - 1) por el tamaño de página.
Ver solución 
SELECT id, nombre
FROM usuarios
ORDER BY registro DESC, id
LIMIT 3 OFFSET 3;

OFFSET dice cuántas filas saltar, no qué página mostrar: la página 2 empieza después de las 3 primeras, por eso es OFFSET 3, y multiplicar la página por el tamaño se salta una de más. El desempate por id es lo que hace que la paginación sea estable: sin él, un usuario podría salir en dos páginas o en ninguna cuando hay fechas repetidas. Ordenar fechas como texto solo funciona con el formato AAAA-MM-DD; en otros motores lo normal es usar un tipo de fecha.

5. Dos registros en uno

Tienes dos listas de horas de eventos ("HH:MM", siempre con dos dígitos), cada una ya ordenada de la más temprana a la más tardía. Escribe combinar_eventos para que devuelva una sola lista ordenada con todas las horas de las dos, incluidas las repetidas. Hazlo recorriendo las dos listas a la vez, sin volver a ordenar.

  • combinar_eventos(["08:00", "09:30", "12:15"], ["08:45", "09:30"]) devuelve ["08:00", "08:45", "09:30", "09:30", "12:15"]
  • combinar_eventos(["10:00"], ["07:00", "11:00", "13:00"]) devuelve ["07:00", "10:00", "11:00", "13:00"]
  1. Lleva un índice en cada lista. En cada paso, el siguiente elemento del resultado es el menor de los dos que señalan.
  2. Con dos dígitos fijos, las horas en texto se comparan bien con <, igual que si fueran números.
  3. El bucle termina cuando una de las listas se acaba, pero a la otra todavía le pueden quedar elementos. ¿Qué haces con ellos?
Ver solución 
def combinar_eventos(a, b):
    i, j = 0, 0
    resultado = []
    while i < len(a) and j < len(b):
        if a[i] <= b[j]:
            resultado.append(a[i])
            i += 1
        else:
            resultado.append(b[j])
            j += 1
    resultado.extend(a[i:])
    resultado.extend(b[j:])
    return resultado

Cada paso mete un elemento y avanza un solo índice, así que se hacen tantas vueltas como elementos haya en total, sin reordenar nada. El fallo típico es acordarse de lo que sobra en una lista y no en la otra: con el primer ejemplo pasa desapercibido porque la lista que queda con elementos es a. Añadir los dos restos no cuesta nada, porque uno de ellos siempre está vacío. sorted(a + b) también acierta, pero no aprovecha que las listas ya venían ordenadas.

6. El segundo sueldo

Muestra en una columna llamada segundo el segundo sueldo más alto de la tabla, contando los sueldos distintos: si el más alto se repite, el segundo es el siguiente valor por debajo. Si no hay un segundo sueldo distinto, la consulta debe devolver una fila con NULL, no una tabla vacía.

  1. Si ordenas los sueldos de mayor a menor, el segundo está en la segunda fila; pero antes asegúrate de que cada valor aparezca una sola vez.
  2. Para quedarte con la segunda fila tienes que saltarte una y tomar una.
  3. Cuando no hay segunda fila, una consulta normal devuelve cero filas. Pero si esa consulta va como subconsulta dentro de un SELECT exterior, su valor pasa a ser NULL.
Ver solución 
SELECT (
    SELECT DISTINCT sueldo
    FROM empleados
    ORDER BY sueldo DESC
    LIMIT 1 OFFSET 1
) AS segundo;

DISTINCT deja un solo 4500, así que el segundo es 3000 y no el 4500 repetido. La consulta interior, cuando no encuentra fila, devuelve nada; envuelta en un SELECT exterior como subconsulta escalar, ese vacío se convierte en NULL, que es lo que pide el enunciado. La versión sin envolver acierta el primer caso y deja una tabla vacía en el segundo. Una alternativa que vale en cualquier motor es SELECT MAX(sueldo) ... WHERE sueldo < (SELECT MAX(sueldo) FROM empleados).
