Entrega 4: limpieza de datos

0 de 6 resueltos

Los datos reales llegan sucios: espacios de más, mayúsculas mezcladas, valores vacíos y repetidos que estropean cualquier conteo. Limpiar es elegir una forma única para cada valor y aplicarla siempre igual, ya sea con strip y lower en Python o con TRIM, LOWER y COALESCE en SQL. Casi siempre conviene limpiar antes de comparar, agrupar o quitar duplicados.

Cómo practicar

  1. Descarga el archivo y ábrelo en tu editor.
  2. Completa las funciones y las consultas.
  3. Ejecuta python entrega_04.py para ver qué casos pasan. Solo necesitas Python: SQLite viene incluido.
  4. Si te atascas, pide una pista. Al terminar, compara con la solución.

Python

1. Correos limpios

Escribe limpiar_correos para que devuelva los correos sin espacios en los extremos y en minúsculas, en el mismo orden. Descarta los None y los que quedan vacíos después de quitar los espacios.

  • limpiar_correos([" Ana@Correo.ec ", "luis@correo.ec"]) devuelve ["ana@correo.ec", "luis@correo.ec"]
  • limpiar_correos([" ", None, "X@Y.EC"]) devuelve ["x@y.ec"]
  1. Trata primero el caso None: no tiene métodos de texto, así que hay que saltarlo antes de nada.
  2. Los métodos strip y lower devuelven un texto nuevo; no cambian el original.
  3. Decide si un correo está vacío después de quitarle los espacios, no antes.
Ver solución 
def limpiar_correos(correos):
    limpios = []
    for c in correos:
        if c is None:
            continue
        c = c.strip().lower()
        if c:
            limpios.append(c)
    return limpios

La trampa es el orden: " " no está vacío, así que pasa el filtro y se convierte en "" al limpiarlo. Por eso primero se limpia y después se comprueba. strip sin argumentos quita también tabuladores y saltos de línea.

SQL

2. Categorías escritas de mil formas

Obtén la lista de categorías distintas, sin espacios en los extremos y en minúsculas. Los productos sin categoría no cuentan. Ordena alfabéticamente. Ojo: algunos valores tienen espacios al principio o al final que la tabla de abajo no deja ver.

  1. Antes de comparar categorías, todas tienen que estar escritas igual: sin espacios en los extremos y en minúsculas.
  2. Puedes aplicar funciones dentro del SELECT y pedir valores distintos sobre el resultado ya transformado.
  3. Una fila sin categoría no es una categoría: descártala.
Ver solución 
SELECT DISTINCT LOWER(TRIM(categoria)) AS categoria
FROM productos
WHERE categoria IS NOT NULL
ORDER BY categoria;

DISTINCT compara los valores tal como salen del SELECT, así que la limpieza tiene que ocurrir dentro de él. Sin TRIM, " bebidas" y "bebidas" cuentan como distintas. Ojo: en SQLite LOWER solo cambia letras sin tilde, así que Á se queda igual; otros motores sí las convierten.

Python

3. Sin repetir, en orden

Escribe unicos_en_orden para que devuelva los valores sin duplicados, conservando el orden de su primera aparición.

  • unicos_en_orden([3, 1, 3, 2, 1]) devuelve [3, 1, 2]
  • unicos_en_orden(["ana", "luis", "ana", "sol"]) devuelve ["ana", "luis", "sol"]
  1. Un conjunto recuerda lo que ya viste, pero no guarda el orden de llegada.
  2. Necesitas dos estructuras: una para preguntar rápido si ya apareció y otra para conservar el orden.
  3. Añade un valor al resultado solo la primera vez que lo encuentras.
Ver solución 
def unicos_en_orden(valores):
    vistos = set()
    resultado = []
    for v in valores:
        if v not in vistos:
            vistos.add(v)
            resultado.append(v)
    return resultado

list(set(valores)) quita los repetidos pero pierde el orden, que en una lista de registros suele importar. Desde Python 3.7 también vale list(dict.fromkeys(valores)), porque los diccionarios conservan el orden de inserción.

4. Ciudades en blanco

Muestra el nombre y la ciudad de todos los clientes, ordenados por id. La ciudad debe salir sin espacios en los extremos. Si falta (NULL, texto vacío o solo espacios), muestra Sin ciudad. Algunos valores tienen espacios que la tabla de abajo no deja ver.

  1. COALESCE sustituye un NULL, pero un texto vacío no es NULL.
  2. Existe una función que convierte un valor concreto en NULL: úsala para que los textos vacíos se traten igual que los NULL.
  3. Quita los espacios antes de comprobar si el texto está vacío: una ciudad con solo espacios también falta.
Ver solución 
SELECT nombre, COALESCE(NULLIF(TRIM(ciudad), ''), 'Sin ciudad') AS ciudad
FROM clientes
ORDER BY id;

NULLIF(x, '') devuelve NULL cuando x es un texto vacío, y entonces COALESCE pone el valor por defecto. Se lee de dentro hacia fuera: limpiar, convertir lo vacío en NULL y rellenar. También funciona con un CASE, pero es fácil olvidar el caso de los espacios.

5. Teléfonos con formato

Escribe normalizar_telefono para que devuelva un móvil de Ecuador en formato 09XXXXXXXX. Quita cualquier carácter que no sea un dígito. Si quedan 12 dígitos que empiezan por 593, cambia ese prefijo por un 0. El resultado solo es válido si tiene 10 dígitos y empieza por 09; si no, devuelve None.

  • normalizar_telefono("099 123 4567") devuelve "0991234567"
  • normalizar_telefono("+593 99-123-4567") devuelve "0991234567"
  • normalizar_telefono("(02) 234-5678") devuelve None
  1. Empieza por quedarte solo con los dígitos, recorriendo el texto carácter a carácter.
  2. El prefijo 593 solo debe cambiarse cuando está al principio y el número tiene la longitud de un número internacional completo.
  3. Haz la validación final, de longitud y de inicio, después de convertir el prefijo internacional.
Ver solución 
def normalizar_telefono(texto):
    digitos = ''.join(c for c in texto if c.isdigit())
    if len(digitos) == 12 and digitos.startswith('593'):
        digitos = '0' + digitos[3:]
    if len(digitos) == 10 and digitos.startswith('09'):
        return digitos
    return None

Reemplazar 593 donde aparezca rompe números que lo llevan en medio, como 099 593 1234. Comprobar la posición y la longitud antes de tocar nada evita esos falsos positivos, y validar al final asegura que cada número devuelto tiene el mismo formato.

6. Estados de pago revueltos

Cada pago tiene un estado escrito a mano. Clasifícalo así, después de quitar espacios y pasar a minúsculas: pagado si es pagado o pagada; pendiente si empieza por pend; revisar en cualquier otro caso, incluidos los NULL. Devuelve cada estado limpio con su número de pagos, ordenado por estado. Algunos estados tienen espacios que la tabla de abajo no deja ver.

  1. Primero limpia el texto, quitando espacios y mayúsculas, y después decide en qué grupo cae.
  2. CASE evalúa las condiciones en orden y se queda con la primera que se cumple; lo que no encaja en ninguna va a ELSE.
  3. Agrupa por el estado ya clasificado y fíjate en qué cuentas: aquí los NULL también son pagos.
Ver solución 
SELECT CASE
         WHEN LOWER(TRIM(estado)) IN ('pagado', 'pagada') THEN 'pagado'
         WHEN LOWER(TRIM(estado)) LIKE 'pend%' THEN 'pendiente'
         ELSE 'revisar'
       END AS estado_limpio,
       COUNT(*) AS total
FROM pagos
GROUP BY estado_limpio
ORDER BY estado_limpio;

COUNT(estado) ignora los NULL y deja el grupo revisar corto; COUNT(*) cuenta filas. En SQLite, LIKE no distingue mayúsculas en letras sin tilde, mientras que en PostgreSQL sí, por eso conviene pasar a minúsculas igualmente. Agrupar por un alias del SELECT funciona en SQLite, MySQL y PostgreSQL, pero no en SQL Server.
